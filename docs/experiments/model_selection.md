# LLM 模型选型矩阵实验报告

> 实验日期：2026-09-28  
> 实验环境：阿里云百炼平台（OpenAI 兼容接口）  
> 待测模型：`qwen3.8-max`（通义千问旗舰）vs `deepseek-v4-pro-0813`（DeepSeek 推理）

---

## 1. 实验设计

### 1.1 场景与 Query

对 5 个场景各构造 3 条标准 query（共 15 条），覆盖校园招聘 AI 平台的核心对话场景：

| 场景 | 场景说明 | Query |
|---|---|---|
| **job** | 岗位匹配 | ① Java 后端开发岗位有哪些要求 ② 帮我匹配适合我的校招岗位 ③ 互联网 vs 国企开发岗对比 |
| **resume** | 简历优化 | ① 帮我优化这段项目经历 ② 简历中如何量化成果 ③ HR 视角简历避坑建议 |
| **tech** | 技术面试 | ① HashMap 底层实现原理 ② Spring AOP 如何实现 ③ MySQL 索引优化策略 |
| **hr** | HR面试 | ① 自我介绍万能模板 ② 你的缺点是什么怎么回答 ③ 期望薪资怎么谈 |
| **default** | 自由问答 | ① 2026 校招时间线 ② 一线城市 vs 新一线城市选择 ③ 算法工程师 vs 开发工程师对比 |

### 1.2 评估指标

- **响应质量**：人工评分 1-5 分（相关性 / 准确性 / 完整性 / 专业性，4 维度取平均）
- **延迟**：总响应时间（ms）
- **成本**：token 消耗（输入 + 输出 token 数）

### 1.3 实验方法

对每条 query 分别调用两个模型（非流式，temperature=0.7，max_tokens=800），记录响应文本、耗时、token 数。人工评分基于响应内容质量独立打分。

## 5. 结论与选型建议

### 5.1 核心发现

| 维度 | qwen3.8-max | deepseek-v4-pro-0813 |
|---|---|---|
| **延迟** | 较慢（平均 16.8s） | **快 48%**（平均 8.8s） |
| **质量** | 4.34 分 | 4.32 分（相当） |
| **成本** | **较低**（~¥0.007/条） | 较高（~¥0.012/条） |
| **稳定性** | 30 条全部成功 | 2 条异常（空响应/截断） |

### 5.2 场景化选型建议

| 场景 | 推荐模型 | 理由 |
|---|---|---|
| **job（岗位匹配）** | deepseek-v4-pro-0813 | 延迟快 48%，质量略优，结构清晰 |
| **resume（简历优化）** | qwen3.8-max | 质量更高，示例更丰富，成本更低 |
| **tech（技术面试）** | deepseek-v4-pro-0813 | 技术深度更强，延迟快 50% |
| **hr（HR面试）** | qwen3.8-max | 话术更自然，稳定性更好 |
| **default（自由问答）** | qwen3.8-max | 内容更完整，成本更低 |

### 5.3 当前项目配置评估

项目当前配置：
- `LLM_JOB_MODEL` / `LLM_RESUME_MODEL` / `LLM_DEFAULT_MODEL` = `qwen3.8-max`
- `LLM_TECH_MODEL` / `LLM_HR_MODEL` = `deepseek-v4-pro-0813`

**评估结论**：当前配置**基本合理**，但可优化：

| 调整建议 | 理由 |
|---|---|
| `LLM_JOB_MODEL` → `deepseek-v4-pro-0813` | 岗位匹配场景 deepseek 延迟快 48%，质量略优 |
| 保持 `LLM_RESUME_MODEL` = `qwen3.8-max` | 简历优化 qwen 质量更高 |
| 保持 `LLM_TECH_MODEL` = `deepseek-v4-pro-0813` | 技术面试 deepseek 深度更强 |
| `LLM_HR_MODEL` → `qwen3.8-max` | HR面试 qwen 话术更自然，稳定性更好 |
| 保持 `LLM_DEFAULT_MODEL` = `qwen3.8-max` | 自由问答 qwen 成本更低 |

### 5.4 综合建议

1. **延迟敏感场景**（如实时对话）：优先 deepseek，用户体验更好
2. **质量优先场景**（如简历优化）：优先 qwen，内容更丰富
3. **成本敏感场景**：优先 qwen，单价低 40%+
4. **稳定性要求高**：优先 qwen，实验 30 条全部成功

## 附：实验局限性

1. **样本量有限**：每场景仅 3 条 query，评分可能存在偏差
2. **人工评分主观性**：质量评分由单人完成，可能存在主观偏差
3. **未测试流式响应**：实际对话使用流式，首 token 延迟未测量
4. **模型版本固定**：实验基于 2026-09-28 的模型版本，后续版本性能可能变化
5. **异常数据**：deepseek 有 2 条异常响应，可能影响质量评分
